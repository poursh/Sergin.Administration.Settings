# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Sergin.Platform is the Platform module (Postgres schema `pf`, module name `Platform`, text key segment `platform`, routes under `/pf/`) of the **Sergin** platform — a .NET 10 modular monolith whose host repo, **Sergin.MeterMinder**, composes it with **DeviceManagement** and **UserAccess**. It holds the features the platform itself needs and has no business domain: localization first (languages and translations, implementing SharedKernel's `ITranslationStore`), later settings and operational monitors. Business features never belong here, and identity and access stay in UserAccess. Design: the host repo's `docs/superpowers/specs/2026-11-05-localization-design.md`, decision 20 onwards.

**This repo is embed-only.** There is no solution file, no `Directory.Build.props`/`Directory.Packages.props`, no dev config here. It only compiles as a git submodule at `src/Modules/Platform/` inside a host repo (today: [Sergin.MeterMinder](https://github.com/poursh/Sergin.MeterMinder)) that also provides `Sergin.SharedKernel` at `src/SharedKernel/`. `dotnet build`/`dotnet test` run against the *host's* solution; the host's root `CLAUDE.md` holds every cross-module convention (layering, CQRS, validation, aggregate features, Blazor views) and this file only adds what is specific to Platform.

## Current state

Two aggregates, `Language` and `Translation`, with their write slices, reads and admin pages.

- **`Language`** (`Languages/` in every layer, no feature level above it): `Audited().Versioned()`, not soft-deletable, not scoped. `CultureName` (max 20) is normalised by `CultureName.Normalise` to `CultureInfo.GetCultureInfo(value, predefinedOnly: true).Name` (`FA-ir` → `fa-IR`) and refuses an unknown culture, the invariant culture and any English culture (`LanguageErrorKeys`, declared in `LanguageTexts`); `LanguageDisplayName` (max 100); `LanguageDirection` `FromCulture | LeftToRight | RightToLeft` and `LanguageStatus` `Draft | Published`, both stored by name. `IsRightToLeft` is derived (`Language.ResolveRightToLeft`), never stored. `ILanguageRepository` declares `IUniqueKeyRepository<CultureName>`; `IsTakenAsync` compares the normalised culture and `ix_language_culture` is the guarantee (migration `AddLanguages`).
- Slices: `AddLanguage`, `RenameLanguage`, `SetLanguageDirection`, `PublishLanguage`, `UnpublishLanguage`, `DeleteLanguage` (a hard delete; its translations go in the same statement through the cascading FK, and the culture's cache entry is refreshed), `GetLanguageById` (versioned), `GetLanguageList` (`LanguageListFields`: search culture and display name, sort by culture). Every write requires `LanguagePermissions.Manage` (`permission.pf.languages.manage`), every read `LanguagePermissions.Read`; all writes but Add `RequireExpectedVersion()`. Each write handler calls `TranslationCacheRefresher.LanguagesChangedAsync` (`.Application/Localizations`) after `SaveChangesAsync`, since the cache loads the language list once; the refresher runs without the caller's token and, if the refresh fails, logs a warning and calls `ITranslationCache.InvalidateLanguages` instead of failing the saved write. The translation handlers call its `TranslationsChangedAsync(culture)`, which refreshes that culture and calls `ITranslationCache.Invalidate(culture)` when the refresh fails. A WebApi endpoint ships per slice.
- **`Translation`** (`Translations/` in every layer): `Audited().Versioned()`, not soft-deletable, not scoped. `LanguageId`, `TranslationKey` (a `TextKey` value as stored, max 300), `TranslationText` (max 4000) and `SourceText` (the catalog default it was translated from, `text`). FK `language_id` → `pf.language` with `ON DELETE CASCADE`; unique `ix_translation_language_id_key` (migration `AddTranslations`). There is no navigation between the two aggregates.
- Slices: `AddTranslation(LanguageId, Key, Text)`, `ChangeTranslation(Id, Text)` (`RequireExpectedVersion()`), `DeleteTranslation(Id)` (versioned; only an **orphan**, a row whose key the catalog no longer declares), `GetTranslationById` (versioned, what Change/Delete are sent at), `GetTranslationList(LanguageId, Module?, Category?, Status?)` and `GetLanguageProgress(LanguageId)`. Writes require `TranslationPermissions.Edit` (`permission.pf.translations.edit`), reads `LanguagePermissions.Read`. Add and Change store `SourceText` = the catalog's current default. Validators (`TranslationRuleBuilderExtensions`): the key is declared (Add; for Change the row's key still is), not yet translated (Add), the text non-empty and ≤ 4000, and **its placeholder set equals the default's** — refused as code `Text` with `platform.translations.errors.placeholders-differ`, `{Expected}` listing the default's placeholders.
- The list is **merged in memory** (`TranslationListMerge`: the catalog's entries × the language's rows read by Dapper) and then filtered (module segment exact, category path or below, status), searched (`Term` over key, default and text, ordinal case-insensitive) and paged by the handler, always ordered by key; `TranslationListFields` declares no sort or filter field. Statuses: `Untranslated` (declared, no row), `Translated`, `NeedsReview` (row's `SourceText` ≠ current default; still served), `Orphaned` (row, no declaration; listed with its stored source as the default, never served). Progress counts Translated + NeedsReview over the catalog's total; orphans count in neither.
- **`PlatformTranslationStore`** (`.Infrastructure/Localizations`) replaces SharedKernel's empty store (`services.Replace` in `LanguageInstallationExtensions`, since `AddSerginCore` registers the default before the module loop). It is a singleton and opens a scope per call for the scoped `IDbConnectionFactory`. `GetLanguagesAsync` reads `pf.language`, drafts included, with the **resolved** direction in `LanguageInfo.IsRightToLeft`; `GetTranslationsAsync(culture)` reads that culture's rows of `pf.translation` (joined to `pf.language`, any status, culture compared without case).

- `PlatformModule` (`Sergin.Platform`) implements `ISerginWebApiModule` and `ISerginWebUiModule`: `Name` `"Platform"`, `Schema` `PlatformDbContext.Schema` (`pf`), the three assembly markers, `UiAssembly` → `PlatformBlazorAssemblyReference.Assembly`; `AddServices`/`MapEndpoints` call `LanguageInstallationExtensions`.
- `PlatformTexts` (`.Application.Configurations`) is the module's text category, `TextCategory.Create("Platform")`, holding `MenuTitle` (`platform.menu-title`, "Platform") — the drawer group's title.
- `PlatformNavigation` (`.Presentation.Blazor`): `Group` is `(PlatformTexts.MenuTitle, Icons.Material.Filled.Settings, Order: 300)`; `Languages` (`/pf/languages`, requires `LanguagePermissions.Read`) is its one entry.
- Pages (view/page split, views under `<Aggregate>/Components/`): `/pf/languages` (`LanguageListView`), `/pf/languages/new` (`LanguageCreateView`, a `SerginFormView`), `/pf/languages/{Id}` (`LanguageDetailView`: progress overview card, Publish/Unpublish, Translations and Delete actions, the direction as a select sent on change, an inline rename `MudForm`; the info button reads `GetLanguageAuditQueryCommand`, global since a language has no scope), `/pf/languages/{LanguageId}/translations` (`TranslationListView`). The translation list's filter panel (module, then category, status) feeds the query's own `Module`/`Category`/`Status` properties rather than `Filtering`: Apply copies the pickers into the applied values the load sends. Inline edit: a row with no translation sends `AddTranslation`; one with a translation loads it versioned when the edit opens and sends `ChangeTranslation` at that version; a refusal is notified as the pipeline returns it, and a stale answer reloads the row's version and says what the translation reads now, keeping the user's text. Only an orphan offers Delete; the edit commands show only to a holder of `TranslationPermissions.Edit`.
- `PlatformDbContext` (`.Infrastructure.Data`) maps schema `pf` with the `AggregateFeatures` override from the start; it does **not** opt into the outbox. Migration `InitialCreate` only ensures the `pf` schema; it was converted to a file-scoped namespace by hand, as every scaffolded migration must be.

## Conventions specific to this module

- Feature folders may carry a feature level above the aggregate (`Localization/Languages/...`) — a feature's aggregates are its text categories (`platform.languages.*`, `platform.translations.*`).
- Permissions are not scoped and named `permission.pf.<resource>.<action>` (`permission.pf.languages.read`).
- Every page route starts with `/pf/`; the host refuses to start otherwise.
- Composing the module into a host takes **two** `ProjectReference`s — `Sergin.Platform` and `Sergin.Platform.Presentation.Blazor` (static web assets do not flow through the plain-SDK composition root) — and one `new PlatformModule()` in the host's modules collection.
